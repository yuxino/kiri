# Kiri UI and README polish plan

Date: 2026-08-11

## Goal

Bring the accepted kawaii-professional visual system and current product behavior to release-preview quality without adding features or changing capture interaction.

## Scope

1. Audit every remaining app surface and public document for stale visuals or behavior claims.
2. Bring the full editor, pinned-image panel, countdown, and menu details into the shared dark overlay system.
3. Restructure the Chinese and English READMEs around a short workflow, grouped capabilities, a real UI preview, OCR instructions, privacy, and accurate recording steps.
4. Correct the Japanese summary, roadmap, and contributor guidance where they contradict current source.
5. Run core tests, strict compilation, nine visual fixtures including the full editor, whitespace checks, stable packaging, and proportional real-app acceptance.

## Acceptance criteria

- Working surfaces remain compact and legible over arbitrary captures.
- Decorative color stays in brand and primary-action areas instead of competing with content.
- README claims match the source: Long Screenshot is absent, OCR requires a dragged region, and recording mode is selected before drawing its region.
- English and Simplified Chinese remain the only claimed UI localizations.
- The installed app retains the stable signing identity and creates no QA capture assets.
